# Continuous video extension

Use `C:\rabbitlands\rabbitlands-client\tools\video-generation\long_video.py` with the project's existing video Python environment. The additional VACE transformer shares the already installed components, so only approximately 7.15 GB of extra weights is needed. Generation is offline; download is a separate command.

The [official VACE guide](https://github.com/ali-vilab/VACE/blob/main/UserGuide.md) recommends generating short clips in sequence using previous-clip conditioning for longer scenes. This helper uses that pattern with black masks on the known context frames and white masks on the future frames to synthesize. The existing context is retained in the assembled movie; its duplicate generated prefix is discarded.

## Create and run a plan

From the client checkout:

```powershell
$VideoPython = '.\.local\video-generation\venv\Scripts\python.exe'
$Scene = '.local\video-generation\sequences\forest'
& $VideoPython tools\video-generation\long_video.py download
& $VideoPython tools\video-generation\long_video.py init --project $Scene --seconds 60 --preset preview --prompt 'A stylized fantasy scene in one continuous shot. The same small white rabbit explores a mossy forest clearing. Warm dawn light, gently swaying ferns, fixed wide camera, consistent character and setting.'
& $VideoPython tools\video-generation\long_video.py run --project $Scene --limit 2
& $VideoPython tools\video-generation\long_video.py status --project $Scene
```

Skip download when the continuation weights are already installed. To extend an existing MP4, add `--source path\to\clip.mp4` to `init`; the source is copied into the new scene folder. Source resolution and 16 fps playback must match the selected preset. Choose an empty scene folder so existing work stays intact.

`plan.json` stores the target seconds, prompt, resolution, per-segment settings, seeds, and conditioning overlap. `state.json` tracks selected segment files and their SHA-256 hashes, previous takes, and assembled previews. All of this remains under the ignored local video tree by default.

`run --limit 2` generates at most two new segments and assembles all completed footage into a playable preview. Repeat that command to continue. Omit `--limit` to run the finite plan through its target duration. Each successful segment is checkpointed immediately. If interrupted, rerun: finished checkpoints are reused, while an unfinished segment may need to render again. The model loads once within each run. Only one runner can mutate a scene at a time.

## Review and iterate

Inspect the newest preview in `renders/`, especially frames on either side of each join. Check character identity, camera direction, lighting, deforming objects, sudden scene changes, and motion stalls. Masks provide temporal context; they do not guarantee perfect consistency indefinitely. Review each small batch before committing substantial generation time to the next one.

Keep stable subject/setting/style details in the main `prompt`. For evolving action, add descriptions under `segment_prompts`, keyed by segment index, for example `"3": "The rabbit turns its head toward the stream."` Indexes start at zero; an imported source occupies index zero. Use scene descriptions rather than editing commands.

To replace a weak continuation:

```powershell
& $VideoPython tools\video-generation\long_video.py run --project $Scene --retry-from 2 --limit 1
```

This preserves old take files and rendered previews, invalidates segment 2 and later checkpoints because they depend on its content, and creates a new take with a recorded seed. Continue with `run` after inspecting it. Changed generation settings similarly invalidate the affected segment and its descendants. A missing or modified checkpoint is rejected; use an explicit retry from that index to repair it. The imported source cannot be regenerated by this command.

To make the same scene longer, increase only `seconds` in `plan.json` and run again. Existing segments remain valid. Each assembly is trimmed to the requested duration at 16 fps, without stretching or looping existing footage. Earlier previews remain available, and every new render has a JSON sidecar recording its plan and source segments.

## Settings and resources

The defaults use a 13-frame context tail (about 0.8 seconds). The 49-frame preview preset therefore adds 36 new frames (2.25 seconds) per continuation. The 81-frame standard preset adds 68 new frames (4.25 seconds). Each invocation keeps the same temporal window, including the final one, and assembly trims surplus frames to the target length. Each model invocation remains bounded to at most 81 frames so total video length does not require holding the whole movie on the GPU. Assembly streams frames rather than loading the whole movie into memory.

Use a preview plan to settle continuity before spending time on a 480p version. Increasing resolution creates a different generation recipe and requires regenerating affected footage; it is not a free upscale. CPU offload and tiled decoding remain enabled. Failures stop the current run and preserve completed work; there is no unbounded retry loop or paid-service fallback.

The artifact-level checks run with:

```powershell
& $VideoPython tools\video-generation\test_long_video.py
```

They verify actual encoded frame order/duration, context masks, checkpoint reuse, changed-recipe invalidation, modified-file detection, and retention of old takes during retry. A real continuation render is still needed to assess visual quality.

## Verified pilot

On the RTX 5080 Laptop GPU, three continuation passes extended the existing 3.06-second forest clip into an 8.00-second export (128 frames, 512 x 288, 16 fps). Two passes ran in one batch; the final pass ran after restarting the process. Earlier checkpoint records and hashes remained unchanged, and another completed run skipped model loading and reused the existing assembly. Frames around all three joins were visually inspected.

The continuation passes took 101-117 seconds each, excluding initial model loading, and peaked at 11.0 GiB of allocated VRAM. Each full preview pass adds 2.25 seconds, so budget roughly an hour for a minute-long preview on this hardware. This is a local benchmark and rough planning estimate; larger resolution, system load, and settings affect runtime.
