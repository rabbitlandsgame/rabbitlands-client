### Named variants of ordinary creatures (2026-09-04)

Salvage register 067. The forum's complaint was not that there was too little
to do at the ceiling; it was that killing the ten thousandth identical wolf is
the same as killing the first. It asked for variety across the whole level
range, and framed it as incremental work rather than one project.

Server-side only — a variant wears its base's body, so the client needs no
change at all.

| Feature | What was asked for | Eloria implementation | Test/evidence | Status |
|---|---|---|---|---|
| Occasional elevated versions | Named versions of common creatures, from the lowest tier upward, each with a better drop table. | `variant_of` and `variant_chance` in creatures.txt: one spawn in N of the named creature is this instead. A variant inherits every field it does not state, so a block is a name, a rarity and the numbers that make it worth meeting - but it is a whole creature, with its own stats, drop table and place in the roster, which is what lets it reuse every existing path rather than needing one for named things. The loader became collect/resolve/build so a variant may be written before its base. | `tests/test_named_variants.py`, 22 cases. Inheritance, file order, and the three refusals: a variant of nothing, a variant of a variant, and one-in-one. | IMPLEMENTED |
| It has to keep happening | A variant rolled only at spawn would fix the world's famous creatures at startup - the named elk immortal, no other elk able to become one. | The roll runs on **respawn** too, from the base rather than from whatever the creature currently is. ## Attributes are bought directly (Other-Life register 007, 009, 010)

The six base attributes are gone on the server. A point used to buy half of
each of two attributes; now it buys the attribute it was spent on. Carry left
Might (009) and one magic number became two (010), so a healer and a battle
mage are no longer the same build.

That is a server change, but it broke this client in a way nothing would have
reported: the statistics window held its own copy of the attribute list.

## Perks bought a tier at a time (Other-Life register 017, 018, 019, 020)

A perk was one purchase. It is now up to three, and the catalogue row stopped
being a description of the perk and became an offer: the price and the words
belong to the tier this character would buy next.

That is the whole reason the tier had to go on the wire. "3 pp" beside a perk
the player already holds reads as a bug unless the window can say which step
those three points buy, and the client cannot work that out from a price.

| Feature | What was asked for | Eloria implementation | Test/evidence | Status |
