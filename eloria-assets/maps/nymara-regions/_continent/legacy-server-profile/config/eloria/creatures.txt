# Nymara creature catalog: 234 normal creatures with distinct updated models
# and seven named bosses sharing their retained base models. The client's production creature catalog is the
# other half of this contract; tests/test_native_actor_model_contract.py holds
# the two together.
#
# level is an explicit balance tier. Attack, defense, attributes, health,
# damage, armor, aggression and respawn values are server-authoritative.
#
# attributes: the twelve cross attributes - matter, toughness, carry, charm,
#   reaction, perception, rationality, magic_offense, magic_defense,
#   dexterity, ethereality, might - by the same names a player carries them
#   under. Each is stated outright, the way a player owns theirs since the six
#   base attributes were deleted.
#
#   Creatures used to be written in those six, and the combat code averaged a
#   pair of them at every read: Might out of physique and coordination,
#   Toughness out of physique and vitality, Dexterity out of coordination and
#   reasoning, Reaction out of coordination and instinct. Every block here was
#   converted through exactly those pairs, so no creature's numbers moved -
#   what moved is that the number the combat code reads is now the number you
#   edit. A block still written in the six is still read, converted the same
#   way, so an old profile or a generator that has not been taught the new
#   names keeps working.
#
#   Five of the twelve are read today: Dexterity to land a hit, Reaction to
#   avoid one, Might behind the damage, Toughness against it, and Magic
#   Defense when a player casts at the creature - the same attribute a player
#   resists a spell with. That last one was Rationality until the creature
#   side caught up with the magic split; each creature's resist number was
#   carried across unchanged, which is why a block's Rationality and Magic
#   Defense start out equal. They are independent numbers from here, and only
#   Magic Defense is read.
#
#   The remaining seven are carried so a creature and a player are described
#   by one set, and are there to be read when something reads them.
#
# footprint: how many tiles the creature stands on, as a box laid around the
#   tile it reports. One number is a square (footprint: 3), two are a
#   rectangle (footprint: 4x2), and the ceiling is 10. Omitted means one tile.
#   These are MEASURED, not chosen - `tools/measure_creature_footprints.py`
#   reads each model's bounding box and writes the value here. Do not hand-edit
#   one without a reason; re-run the tool instead, and it will tell you every
#   creature whose value no longer matches its model.
#
# scale: how large the model is drawn, as a multiple of the GLB as authored.
#   Omitted means 1.0, the model at its own size. For a species that should be
#   a bigger or smaller version of another without a second model to maintain.
#   Between 1/128 and 128. The actor packet carries it as a 16-bit field
#   holding the base-two logarithm of the scale, so every power of two in
#   that range is exact and everything else is within a sixtieth of a
#   percent.
#
#   A creature much past about 10x will be drawn larger than the ground it
#   can be given: footprints stop at 10x10, because a path search places a
#   body by its area and a hundred-tile creature is scenery rather than
#   something that walks. The tool says so when it happens.
#
# variant_of / variant_chance: this block is an occasional elevated version
#   of another creature - one spawn in `variant_chance` of that creature is
#   this instead. It inherits every field it does not state, so a variant
#   block is a name, a rarity and the few numbers that make it worth
#   meeting. It needs its own drop table, it counts in the roster, and it
#   is never placed in spawns.txt - it appears by rolling in place of the
#   creature it elevates, including on respawn.
#
#   It wears its base's body, so it may not disagree about actor_type or
#   footprint: the client is told one footprint per actor type, and the two
#   would be drawn standing on different ground.
#
#   A scale change is not complete until the tool has been re-run: the
#   footprint is measured from the model INCLUDING its scale, so a creature
#   drawn twice as large must also hold four times the ground, or it is the
#   same bug this whole feature exists to fix. The container build re-runs
#   it, so an image is never wrong - but the committed profile can be, and
#   `tests/test_creature_extents.py` is what says so.

# --- Named variants -----------------------------------------------------------
#
# Occasional elevated versions of ordinary creatures. A variant states only
# what differs from the creature it elevates; everything else - actor type,
# footprint, aggression, respawn, the lot - is inherited from that block.
#
#   variant_of:     the ordinary creature this is a version of
#   variant_chance: one spawn in this many is this instead
#
# A variant is a whole creature: it needs its own drop table in drops.txt, and
# it counts in the roster. It shares its base's body, so it may not disagree
# with it about actor_type or footprint - the client is told one footprint per
# actor type, and the two would draw on different ground.
#
# Deliberately spread across the whole level range rather than sitting at the
# top: the point is that any creature you fight might turn out to be the
# famous one, not that there is more to do at the ceiling.






# --- Bosses -------------------------------------------------------------------
#
# A creature that exists only to be a boss. The other kind of boss - a bigger,
# tougher one of an ordinary species - needs nothing here: an invasion group
# names the species and multiplies its numbers. This is for a boss that is its
# own animal, with its own level, its own numbers and its own drop table.
#
#   boss: 1     never spawned by spawns.txt and never rolled as a variant
#
# Being a boss is what makes it bigger, not this file: an invasion draws its
# boss enlarged, and larger again for a strong strength roll. `scale` here is
# what the model is, and it is bound by the same rule as everywhere else - the
# footprint is measured from the model including it.
#
# It shares a body with the species whose actor_type it wears, so like a
# variant it may not disagree with that body about footprint - the client is
# told one footprint per actor type. What makes it a boss rather than a
# variant is where it comes from: a variant is rolled wherever its base
# spawns, and a boss is placed by an invasion when the invasion earns one.
